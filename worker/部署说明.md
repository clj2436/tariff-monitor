# 配置代理 Worker 部署说明

作用：网页**不接触 GitHub PAT**。你只需在页面填入「Worker 地址 + 配置密码」，密码由 Worker 在服务端校验，校验通过才用 Worker 自己持有的 PAT 写入 GitHub。这样密码是真正的安全边界——改前端 JS 也绕不过去。

## 一、创建 GitHub 细粒度 PAT

1. 打开 https://github.com/settings/personal-access-tokens/new
2. **Resource owner** 选你自己；**Repository access** 选 `Only select repositories` → 勾选 `tariff-monitor`
3. **Permissions** 添加两项：
   - `Actions` → `Access: Read and write`（用于写 Secrets / Variables）
   - `Contents` → `Access: Read and write`（用于读写 `data/watch_config.json`）
4. 生成后复制 token（`github_pat_...`），**只填到 Worker，不要填到网页、不要提交**。

## 二、创建 Cloudflare Worker

1. 登录 https://dash.cloudflare.com → 左侧 **Workers & Pages** → **Create** → **Create Worker**
2. 命名为 `tariff-config`（或任意），点 **Deploy**
3. 进入该 Worker → **Edit code**，把本目录 `worker/index.js` 的**全部内容**粘贴进去覆盖默认代码 → **Deploy**
   - `index.js` 已内联加密库，单文件、无需 npm、无需命令行。

## 三、配置 Worker 密钥（关键）

进入 Worker → **Settings** → **Variables and Secrets** → **Add**，逐个添加（类型选 **Secret**，值会被加密存储、不可回读）：

| 名称 | 值 | 说明 |
|---|---|---|
| `SITE_PASSWORD` | 你自定的配置密码 | 页面要填的密码，**建议 16 位以上随机串**（见第五节） |
| `GITHUB_PAT` | 第一步生成的 PAT | Worker 用它写 GitHub |
| `REPO` | `clj2436/tariff-monitor` | 目标仓库 owner/repo，按实际改 |

可选（同样 Secret）：

| 名称 | 值 | 说明 |
|---|---|---|
| `ALLOWED_ORIGIN` | `https://其他域名,http://localhost:8080` | **追加**允许的页面来源，逗号分隔；`https://zf.chenlijun.eu.org` 与 `https://clj2436.github.io` 已内置，不用填 |

> 改完 Secret 需要 **Deploy** 一次才生效。

**站点域名**：仓库根 `CNAME` 已设为 `zf.chenlijun.eu.org`，Worker 默认放行该域名；用哪个域名打开页面都能正常调用。若以后加新域名，在 `ALLOWED_ORIGIN` 里追加即可。

## 三之二、两套钉钉机器人（重点 / 其他）

推送分两路，建议各建一个钉钉群机器人、分别填到订阅页 ③：

| 路线 | 对应源 | Secret 名（Worker 写入仓库） |
|---|---|---|
| ★重点 | 移动/电信/联通/广电重点专项 + 四川联通专项 | `DINGTALK_WEBHOOK_FOCUS` / `DINGTALK_SECRET_FOCUS` |
| 其他·X | 移动/电信/联通/广电全量（非重点省份） | `DINGTALK_WEBHOOK_OTHER` / `DINGTALK_SECRET_OTHER` |
| 通用兜底 | 两路专用都没填时共用 | `DINGTALK_WEBHOOK` / `DINGTALK_SECRET` |

- 想两路分开：在订阅页 ③ 分别填「① 重点机器人」「② 其他机器人」的 Webhook 与加签密钥 → 保存。
- 想两路发到同一个群：只填「通用兜底」即可，Worker 会回退到它。
- 加签密钥以 `SEC` 开头；若机器人安全设置用的是关键词校验，密钥留空。
- 点仓库 Actions 里的「测试通知通道」可一次验证两路是否都填对（会以各自机器人发一条测试消息）。

## 三之三、本轮全部变化报告页（钉钉消息里的链接）

钉钉消息受长度限制，正文只展示前 N 条（默认 30）。现在每次推送会额外生成一份**自包含 HTML 报告**，消息开头有醒目的「👉 查看本轮全部 N 条变化明细」链接：

- 点开后可**搜索**（名称/编号/变更说明）、按**运营商/类型**筛选，每条可展开看**修改前后对比**。
- 报告由 `scripts/build_report.py` 生成，写到各家 `data/ops/{op}/report.html`，随该家数据一起由 Actions 提交，无需你手动操作。
- 链接地址 = `SITE_URL + /data/ops/{op}/report.html`。`SITE_URL` 在订阅页 ③ 配置；**不配也能用**——脚本默认用 `https://zf.chenlijun.eu.org`（仓库根 CNAME 的域名）。
- 报告页完全静态、数据内嵌，点开即看，不依赖主页面加载上百 MB 的资费数据。

> 想让链接指向别的域名（比如 `clj2436.github.io`），在订阅页 ③ 的 `SITE_URL` 里填即可，留空表示不改。

## 四、在网页使用

1. 打开站点的「订阅推送」页 → ③ 钉钉机器人参数
2. ④ 配置代理与凭证：
   - **Worker 地址**：填第二步部署后的地址，形如 `https://tariff-config.你的账号.workers.dev`（存本机）
   - **配置密码**：填 `SITE_PASSWORD`（只存内存，刷新需重填）
3. 要改 Webhook / 密钥 / 通道 / 站点 → 填好上方参数 → 点 **保存机器人配置到 GitHub**
4. 要改关注省份 / 消息上限 → 勾选好 → 点 **同步关注规则到仓库**
5. 状态提示会显示每项写入结果；失败会给出具体原因。

## 五、安全说明

- PAT 与密码都只在 Worker 服务端，页面和浏览器都不保存密码（Worker 地址会存本机）。
- 密码在 Worker 端用恒定时间比较校验，错误直接 401。
- Worker 对要写入的值做白名单校验（Webhook 必须是钉钉地址、通道只能是 dingtalk/all、上限 1-200 等），防止被当作通用 GitHub 代理滥用。
- Secret 用 GitHub 仓库公钥做 libsodium sealed box 加密后上传，与 GitHub 官方要求一致。
- **防爆破**：Worker 按请求 IP 记录失败次数，连续 5 次密码错误锁定 15 分钟（返回 429 + `Retry-After`），同一 IP 两次尝试至少间隔 400ms；登录成功后清零。密码仍是第一道门槛，**请务必设 16 位以上随机串**（如 `openssl rand -base64 24` 的结果），不要用生日/手机号。
  - 免费额度下锁定状态存在 Worker 实例内存中；多节点/重启后计数会重置。想跨节点持久限制，可在 Cloudflare 建一个 KV namespace 并以变量名 **`AUTH_KV`** 绑定到该 Worker（Bindings → KV Namespace），代码会自动优先用它。
  - 更稳的做法：在 Cloudflare 控制台对该 Worker 路径再加一条 **Rate Limiting** 规则（如每 IP 每分钟 20 次请求），与 Worker 内锁定叠加。
- 只允许内置两个站点域名调用（`zf.chenlijun.eu.org`、`clj2436.github.io`）；其他来源可在 `ALLOWED_ORIGIN` 追加，不在列表的来源直接 403。
- 钉钉推送侧也做了限流保护：任意两次发送最小间隔 1 秒（两路机器人之间也算），遇限流按指数退避 + 随机抖动重试（默认 4 次），并解析服务端返回的等待秒数；单条消息超 12000 字符自动截断。对应环境变量 `DINGTALK_SEND_GAP` / `DINGTALK_MAX_RETRIES` / `DINGTALK_MAX_CHARS` 可按需在 Actions Variables 调整。

## 六、更新

以后若修改了 `worker/index.js`，重新进入 Worker → Edit code → 粘贴新内容 → Deploy 即可。页面侧无需改动。
